# RQ1 analysis contract

Run the analysis on completed raw logs after the evaluation panel and comparison are frozen:

```sh
PYTHONPATH=src python -m taps_rebuild.specialization --root ROOT --manifest configs/rq1/study.json --output outputs/rq1/study/report.json --markdown outputs/rq1/study/report.md
```

Research analysis requires Slurm. Small engineering fixtures can run locally. Existing reports are never overwritten. The module reads logs and training receipts; it does not launch training, evaluation, or model downloads. `configs/rq1/manifest-schema-fixture.json` is a schema fixture containing placeholder paths and hashes, with engineering scope. It is not an experiment or a result.

The manifest identifies one target checkpoint, an explicit held-out panel, a common evaluation budget, traffic weights, and matched training-seed cohorts. Every cohort contains exactly one generalist and one specialist for every domain. Every drafter must be evaluated on the entire cross-domain panel. Each input descriptor is an object with `path` and the SHA256 of the exact file bytes. Paths are relative to `--root` unless absolute. Logs and the panel are JSONL; training evidence is JSON. A drafter can list several log shards, which are checked together for duplicates and complete coverage.

The panel contains one row per expected generation, with `domain`, `question_id`, `turn_id`, `repeat`, `seed`, `prompt_id`, and `prompt_sha256`. `prompt_id` identifies a whole held-out question or conversation and remains constant across its turns and repeats. It must not identify different questions or domains. `prompt_sha256` identifies the exact model-input token sequence for that turn; derive it from an unambiguous serialization of the actual token IDs. The turn-specific evaluation seed can differ across turns but must match between every drafter. Within a question, every planned repeat must contain the same complete turn set. There is exactly one seed per question/turn/repeat.

Measured log rows contain those panel fields plus:

- `status: "completed"`, an explicit Boolean `warmup`, and `generation_mode: "speculative"`.
- `scope: "research"` or `"reference"` for research eligibility.
- `target_identity_sha256` and `drafter_checkpoint_sha256` identifying the actual loaded weights.
- `evaluation_budget`, exactly equal to the manifest object. It includes positive `max_new_tokens`, positive `verifier_nodes`, and nonnegative `temperature`; retain context, batch size, tree depth, top-k, dtype and other controlled settings in the same object.
- `cycles`, `cycle_count`, `new_token_count`, `output_token_ids`, `comparison_token_ids`, and positive measured `wall_ms`.
- Optional `unused_final_drafting_ms`, retained separately and included in total drafting overhead.

Every explicit cycle has nonnegative `accepted_draft_tokens`, positive `emitted_tokens`, nonnegative measured `drafting_ms` and `verification_ms`, positive `verifier_nodes`, and nonnegative `proposed_nodes`. `accepted_draft_tokens + 1 == emitted_tokens`. The cycle-list length equals the true `cycle_count`; emitted counts sum to `new_token_count`, which equals the raw output-token-list length. `raw_reported_idx` is ignored. Each cycle must use the manifest's fixed verifier-node budget. Raw block overshoot is retained, while comparison tokens are the raw prefix through the first EOS/eot inclusive, then capped at the requested budget. The logger must supply that prefix; analysis validates prefix consistency and its length, not the tokenizer's stop-token semantics.

Each drafter descriptor includes `id`, `role`, optional specialist `domain`, `training_seed`, `checkpoint_sha256`, `target_identity_sha256`, `training_evidence`, and `logs`. Training evidence must bind the receipt to the checkpoint, training seed and target. It records `status: "complete"`, `scope: "research"`, the checkpoint and target hashes, `training_seed`, `domains`, `response_regime` (`target_generated` or `original`), and `architecture_identity_sha256`. The generalist's domains are the complete manifest domain set; each specialist's domain set contains its one domain. Architecture identities must match within a comparison, and response regimes must match. Analyze original-response and target-generated studies separately.

Training evidence has `observed` and `declared` objects, each containing positive integer `loss_tokens` and `optimizer_steps`. Observed and declared counts must agree and must match between each specialist and its generalist. These counters do not establish matched compute.

To establish compute matching, the same evidence additionally contains `compute` with `kind` equal to `measured_flops` or `measured_gpu_seconds`, a positive measured `value`, `measurement_protocol_sha256`, and `measurement_scope`. For GPU-seconds it also contains `hardware_identity_sha256`. The metric kind, measurement protocol and scope must match. GPU-seconds additionally requires identical hardware identities. Relative compute difference is `abs(specialist - generalist) / generalist`, compared with the manifest's preregistered `relative_compute_tolerance` (default 1%, maximum 10%). FLOPs must be measured by the declared profiling protocol; GPU-seconds must be obtained from actual training device time or training wall time under that protocol. Neither is reconstructed from token counts, optimizer steps, acceptance length, parameter count, or evaluation time. Keep the underlying measurement logs and protocol alongside the receipt. A missing compute measurement yields an ineligible matched-compute comparison rather than an assumed match.

Canonical raw acceptance is computed exactly as in `metrics.py`: sum raw emitted tokens and true verification cycles across all turns within each question/repeat, divide those sums, average repeat ratios within the question, then average questions. A turn-specific seed never divides one question-repeat. Equal-turn averages are retained only as diagnostics. Comparison-token throughput uses actual measured wall time and includes the terminating token; raw throughput and discarded overshoot are separate diagnostics. No speedup is derived from acceptance.

The primary specialization contrast uses a fixed domain oracle: each held-out question goes to the specialist trained for its declared domain. It does not select the drafter with the best measured test outcome. First compute each question's specialist-minus-generalist difference within each matched training seed, then average the observed seed differences per question. Domain means are combined using the declared traffic weights. When weights are omitted, the expected panel's prompt fractions are used. The cross-domain matrix retains every drafter/domain/seed cell.

Intervals resample whole questions with replacement within each domain, retaining every turn, repeat and observed training seed, with fixed traffic weights. They are prompt-cluster percentile bootstrap intervals conditional on the observed training seeds. The report additionally includes training-seed gap SD; it does not label prompt-bootstrap intervals as uncertainty across unseen training seeds. A paired two-sided sign-flip test is exact for at most 16 prompt clusters and uses a seeded Monte Carlo test with a plus-one correction otherwise. Its exchangeability assumption is stated in the report. Per-domain and cross-domain intervals are exploratory and are not multiplicity adjusted.

Any missing, unexpected, duplicate, prompt-mismatched, seed-mismatched, target-mismatched or evaluation-budget-mismatched generation prevents a paired claim. Duplicates and malformed raw counters fail validation. Missing or unpaired panels produce coverage diagnostics and descriptive matrix values, but the specialization gap and its interval are withheld; the code never silently analyzes a common-case intersection. A missing role in any training-seed cohort also withholds the gap.

Complete but unmatched-compute panels can have an explicitly exploratory descriptive gap; scientific comparison eligibility remains false. Engineering/synthetic manifests always remain ineligible. Scientific comparison eligibility additionally requires at least three matched training-seed cohorts, at least two prompt clusters per domain, complete training identities and budget evidence, and no T=0 comparison-output mismatch. A checkpoint reused across different training-seed cohorts is flagged. This eligibility concerns the declared RQ1 comparison only: it does not establish target-only correctness, full-model T=1 distributional correctness, absence of training/evaluation leakage, successful official reproduction, or publication readiness. Those require their separate audits and gates.
