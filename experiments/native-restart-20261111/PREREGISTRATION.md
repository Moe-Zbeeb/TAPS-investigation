# Native process-restart control · 11 November 2026

This is engineering qualification for restarting the pinned native EAGLE-3 recipe, not scientific training or evidence that a drafter improved. Use the exact authored 32-train/eight-dev synthetic fixture and released drafter initialization on all eight A100s. Keep the target, native source revision, preprocessing, vocabulary, optimizer, FP16 dynamic scaler, schedule and original loss unchanged.

Prepare two fresh plans. The uninterrupted control completes two successful optimizer updates. The interrupted plan commits after its first successful update, exits every worker process, then starts fresh distributed worker processes under the same plan and physical GPU mapping and completes its second successful update. The data loader has four microbatches per rank in the first epoch, so the first successful update may fall in a later epoch if dynamic scaling skips early updates. Require the committed cursor to be strictly inside an epoch for the mid-epoch claim; an epoch-boundary checkpoint alone fails this qualification.

Use opt-in executable AST hooks against the hash-pinned upstream main, leaving its bytes intact. Replace only its epoch checkpoint discovery and epoch/batch iteration, then append a commit hook after each completed training batch. Preserve the actual loss, native per-batch zeroing, sampler `set_epoch(epoch+1)`, optimizer and evaluation. Commit only at a successful optimizer boundary, after the original batch logging and epoch-metric accumulation. Store DeepSpeed model/optimizer/scheduler/scaler state, rank-local Python/NumPy/CPU-CUDA RNG, sampler identity, epoch and next batch, accumulated epoch metrics and token counters. Bind all checkpoint files to the plan and physical GPU identity. Restore data position using the deterministic pinned tokenized dataset/collator; after replaying loader setup and skipped batches, restore the saved training RNG before the next forward. This is not a general guarantee for stochastic data augmentation.

Require all eight resumed ranks to recover exact trainable, optimizer/scaler, scheduler and counter identities, restore RNG/cursor, and finish two successful updates. Compare final trainable/optimizer/scaler/scheduler identities, final RNG identities, and the entire observed per-rank training-batch sequence with the uninterrupted control. No tolerance-based model/optimizer waiver is allowed. Learning-rate values alone may use the existing 1e-12 relative / 1e-15 absolute roundtrip tolerance. A mismatch fails the qualification and remains recorded.

Checkpoint files are trusted project-local artifacts, bound by file hashes before deserialization. Only explicit `resume` may reopen a stopped recovery-enabled plan; the normal launcher remains single-use. Retain separate attempt receipts and batch/step journals. No trained-quality or full forty-epoch result is claimed by this control. Independent scientific validation remains required before real-data training.
