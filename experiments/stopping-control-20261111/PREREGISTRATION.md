# Fixed output-budget control · 11 November 2026

This diagnostic is registered after observing two context-stop length differences and one FP32 token disagreement in the original 1,120-pair greedy panel. It is a new control, not a replacement for the failed panel or a retrospective pass. It does not admit training or claim universal losslessness.

Use all 1,120 frozen question/turn inputs, their original seeds, models, source revisions, native tree settings and FP32 precision: EAGLE-3 480 pairs, EAGLE-2 320, HASS 320. Keep the original cache capacity of 2,048 and requested output ceiling of 512. Before generating either member of a pair, calculate `B = min(512, 2048 - ea_layer.total_tokens - 10 - prompt_tokens)`. Reject any input with B < 1. Both paths receive B as their generation ceiling. The observable completion is the first B raw output tokens, ending inclusively at the first native EOS/eot terminal if earlier. This limit never depends on either realized output length. Reject a shorter unterminated output. Retain all raw tokens, cycles, actual overshoots, the prior 512-token projection, and the predetermined B.

Compare these observable token sequences exactly. No logit tolerance, tie waiver, failed-case exclusion or input substitution is allowed. Report every mismatch and its rate by method and benchmark. The previous MT-Bench token decision is expected to remain a failure unless the changed generation ceiling demonstrably changes its prefix; document the result. The two known CNN/DM cases should agree within the predetermined common output budget; this is a hypothesis to test, not an admission decision.

Run every method over all eight GPUs in one owned A100 80GB node, with one shard per physical GPU. Native upstream files and active project source remain frozen. Reuse only the pinned observational GPU-context policy for the known absent-PID driver context on node11; no other resident application is allowed. This control makes no timing or memory-performance claim.

Freeze the wrapper, budget helper, original collector, registration, context helper/policy and registered cases by hash. Each worker retains original source/model provenance. A CPU Slurm replay must reconstruct the token projections, coverage, predetermined budgets and exact equality from raw journals. Completion means diagnostic coverage and evidence are complete; a mismatch is still a mismatch. Independent review of numerical/stopping policy and the temperature-one validator remains a separate requirement.
