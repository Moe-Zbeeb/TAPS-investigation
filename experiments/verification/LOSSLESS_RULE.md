# Fixed-tree verification rule

This is a mathematical statement about exact conditional target distributions. Floating-point kernels, masks, cache commits and stopping behavior require separate implementation checks.

Fix a verified prefix and a candidate tree built using draft-side information. At a node, let q be the target distribution conditional on the verified prefix. Deduplicate the proposed child token IDs and choose their order before the verification random draws. Set the residual distribution to q. Try each child token x with probability equal to its current residual probability. On rejection, remove x and renormalize. If every child is rejected, sample from the residual and emit that token. On acceptance, emit x and continue at the matching child. A zero-probability child is rejected; a probability-one child is accepted, so a zero-mass residual is never sampled.

Let R_i be the target mass remaining before the ith distinct child. The probability of reaching that trial is R_i: initially both are one, and rejection multiplies the reach probability by (R_i - q(x_i))/R_i. Consequently the unconditional probability of accepting x_i is R_i q(x_i)/R_i = q(x_i). After all rejections, the fallback contributes q(x) to every token outside the child set. Thus the emitted token has distribution q. Applying this argument inductively at each emitted prefix gives the target continuation distribution, including when proposals depend on previously verified history. Proposal selection must not use fresh verifier random draws. Duplicate tokens are tried once; their expert provenance may be retained separately.

For a target-sampled root, the root itself already has the correct target law. A greedy run instead chooses the target argmax at every verified position. The configured budget includes this common root, so a budget N leaves at most N-1 additional draft nodes.

For each non-root candidate node v, let pi(v) be the conditional target probability of its entire path after the common root. With candidates fixed, the node is accepted exactly when the target continuation follows that path. Therefore expected accepted draft tokens equal the sum of pi(v) over retained non-root nodes. Path probabilities cannot increase with depth. The top N-1 nodes by exact pi, with ties ordered by depth and a fixed deterministic path order, are prefix closed and maximize this sum among feasible trees from the pool. This conclusion concerns exact probabilities. Estimated calibrator scores require empirical evaluation; it does not establish a measured latency or throughput advantage.

The research implementation is in composition.py. Released posterior functions are additionally tested on finite vocabularies, including duplicate candidates and fallback sampling. Released-model greedy checks compare actual tokens. A full-model temperature-one empirical audit is still required; neither this argument nor those smaller tests establishes production kernel correctness.
