## Feasibility and scope

The original generator derives each turn's seed from the registered global seed, example ID and turn index. It can therefore supply a shared queue without making seeds depend on worker assignment. The exact original function and helper package must be imported from hash-pinned source snapshots. A new versioned generation plan should state that hardware, batching and cache history may change FP16 greedy near-tie decisions; it should not claim byte-identical continuation. Original committed responses take deterministic precedence over any overlapping bootstrap outcomes, while redundant bootstrap data remain evidence. The bootstrap's 512 outcomes include legitimate exclusions; every second-node GPU must also demonstrate actual forward work and complete response generation.

Two full eight-GPU nodes fit the user's 18-GPU high-priority allowance. Their assignment, live owners, physical UUIDs, runtime and model/tokenizer settings need actual verification. The protected holder and holding successor are distinct from the data coordinator and workload step. Only the latter may be stopped after qualification. The old workload must be resolved from current state and its frozen teacher-plan identity, including across allocation deadlines; historical step IDs or matching job names alone are insufficient.

## Findings communicated during implementation

The first reviewed `corpus_parallel.py` identity was `b2eac53d896a72aa0a3994f9666286cc60ca939404fb9f7919190f40ccda2190`; an expanded snapshot was `a0e838c4b0782d24e44701b567cd4e6b5bb2b57666e26d8fe7891d35ff123676`. Source changed while findings were being communicated. These are checkpoint findings and must be reevaluated on final frozen bytes.

- **Node identity:** worker metadata and its attempt comparison use `socket.gethostname`, while allocation records and the lock-proof node set use short Slurm names. Valid FQDN hostnames can fail both checks before or after the old workload is stopped. Normalize consistently from Slurm/short hostname and retain the full hostname separately if useful.
- **Migration and merge recovery:** the first prepare implementation required the old coordinator to remain RUNNING and reused exclusive-create paths after cancellation. Later revisions permit a cancelled coordinator with durable intent and use preparation-attempt paths. Remaining boundaries include accounting after `scontrol` ages out a job, natural holder/successor rollover, cancellation between intent publication and action, and interrupted final corpus writes. A finish retry must not fail solely because its prior attempt created a partial final directory.
- **Immutable publication:** an early prepare invocation checked for a plan before acquiring old locks, allowing a second invocation to replace a published plan after waiting. Hold a separate migration lock for the whole operation, recheck under it and publish the final plan without replacement. Result files likewise require atomic no-clobber publication and file plus parent-directory durability. Later source revisions added migration locking, unique temp names, hard-link no-clobber publication and directory fsync; final tests must cover those paths.
- **Busy is not complete:** an initial `claim` returned no work when every outstanding task was merely locked, and workers exited. A failed last in-flight worker could then leave unclaimed work with no survivor. Distinguish busy from globally complete and keep healthy workers waiting. A later API returns `(-1,None)` for busy; the caller must handle that sentinel before indexing tasks or closing a lock.
- **Cross-node proof recovery:** a partial lock probe leaves a marker and observer files. Reusing them without an attempt nonce can either reject a valid restart because the old owner no longer holds the lock or count stale observations for a new owner. Bind the challenge, owner and observers to a live attempt/probe nonce. Proving NFS behavior with a CPU observer on the old allocated node before stopping generation would reduce transition risk.
- **Automatic continuation:** a one-shot attach loses the old node's workers when its protected allocation expires. A frozen supervisor/DAG must attach the same task plan to the live successor and recover eligible second-node interruption without resetting completed chunks or exceeding the GPU allowance. Correctly retaining chunks is distinct from automatically keeping both nodes running.
- **Provenance closure:** bind all eight bootstrap proof files and node-attempt identities into the sealed plan. Validate each committed result's worker, source bootstrap, target, runtime and physical device mapping against its bound attempt, including recovery attempts. Merely saving optional metadata is insufficient for the final receipt's provenance claim.
- **Memory and streaming:** the observed prepare stores all parsed preserved outcomes, while finish stores every serialized outcome in a list. Memory grows with the full response corpus, not just 540,107 integer ordinals. Use a disk-backed ordinal index or bounded source/result streams, or establish and enforce a measured safe resource bound before stopping the old job.

The new code correctly begins isolating the frozen original package, comparing immutable source fields and complete user-turn sequences, copying original journals, preserving incomplete-tail boundaries/hashes, keeping original outcomes on bootstrap overlap, and enforcing unique full ordinal coverage. These are useful foundations. They do not substitute for recovery, source-binding and actual two-node qualification checks.

No GPU migration or existing job mutation was performed by this reviewer. A lightweight local busy-queue probe observed the later busy sentinel rather than global completion; it did not exercise real NFS, vLLM or a cluster transition. Production migration approval remains pending final-source review and appropriate execution evidence.
